# Decisions

## D-001 — Purpose before platform

CKF is a living relational feedback instrument, not a graph visualiser or AI chat assistant. Every feature must improve the live message-to-feedback loop.

## D-002 — Beeper companion

Use Beeper as the first multi-network read-only integration. Pin one DM rather than infer another application's active window. Polling reconciles the experimental WebSocket.

## D-003 — Private to shared

Automatic analysis begins private. Sharing releases a reviewed derived subset. Shared jointness requires affirmative acts by all represented participants.

## D-004 — Separate truth domains

Raw source events live only in the encrypted local ledger. Derived private and shared fields are separate documents. Shared CRDT state cannot reference undisclosed raw content.

## D-005 — Incremental proposals

Models propose schema-valid patches against a bounded field neighbourhood. Validators—not the model—enforce evidence, attribution, lifecycle, visibility, and jointness invariants.

## D-006 — Bootstrap, do not fork

Adopt commodity infrastructure through owned interfaces; extract narrowly attributed patterns; use heavy systems as evaluation competitors. Do not inherit a whole upstream application ontology.

## D-007 — Stable dependency floor

Pin Automerge Repo 2.5.6 rather than the 2.6 alpha line. Record all pins and upgrade only behind verification.

## D-008 — Pilot runtime

Ollama may accelerate M2 research, but the pilot must use a managed local `llama.cpp`-compatible runtime and model download.
