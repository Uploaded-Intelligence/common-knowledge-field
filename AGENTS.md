# Common Knowledge Field — Local Operating Contract

The global Lead-Orchestrator constitution applies. This file adds CKF-specific constraints.

## Winning

- `docs/WINNING.md` is the terminal product contract.
- `docs/PROGRESS.md` is the canonical current state.
- Every implementation task must cite an acceptance gate and produce fresh evidence.
- A build or attractive graph is not completion; the live relational feedback loop must be demonstrated.

## Safety and product invariants

- AI output is always provisional until a participant explicitly judges it.
- `jointly_ratified` requires affirmative judgments from every represented participant.
- Every visible semantic unit must resolve to valid evidence.
- Raw message content must never enter shared CRDT documents, relay logs, analytics, or crash reports.
- Beeper access is read-only in MVP. Never send, edit, react, or delete source-chat content.
- Do not infer hidden personality, diagnosis, emotion, motive, or intent.
- No cloud-model fallback.
- No public deployment or repository visibility change without explicit user approval.

## Engineering

- TypeScript uses strict mode and production behaviour is developed test-first.
- Preserve append-only revisions; corrections supersede rather than rewrite history.
- Keep upstream systems behind CKF-owned interfaces.
- Concurrent implementers use separate branches and worktrees.
- Commits use `Uploaded-Intelligence <148705917+Uploaded-Intelligence@users.noreply.github.com>`.
